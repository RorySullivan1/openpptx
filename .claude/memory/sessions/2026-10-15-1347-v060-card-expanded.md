## Gotchas & dead ends
- 0.5.1 kept a path source open until GC (reader in a ref cycle), so on Windows the file was locked; the loader now closes it.
- `hasattr(part, "sha1")` (SVG guard in `_find_by_sha1`) evaluates the lazyproperty, so it reads every image.
- Reopening the zip costs ~0.55 ms (336 entries); 100 reads took 69.5 ms reopening vs 11.6 ms through one handle.
- The perf corpus reuses one PNG, and `add_picture` dedupes by SHA-1, so `large`'s "10 images" is a single part.
  A memory benchmark needs distinct images (card: `IMAGES_100`, 100 noise PNGs).
- `_ZipPkgReader` already reads members on demand. The eager read is in `_PackageLoader._parts`
  (`blob=package_reader[partname]`), and the loader is transient, so the zip closes after load.
- `_find_by_sha1` (image/media) and `_import_part`/`_find_identical` compare every part's blob. Under lazy
  blobs they would read everything, so the card adds size prefilters.
- Saving over the source path would truncate the file under lazy reads, so the blobs must be copied into memory first.
- The lazyproperty count is 204 in 45 files (the earlier "206/47" was stale).
- Two proxies for one shape is ordinary (`slide.shapes[0]` builds a new one each call), so Python-side snapshots
  (`FillFormat._fill`, `ColorFormat._color`, `AdjustmentCollection`) lost writes; they now validate against the XML.
- cProfile "primitive" calls skip a re-entered function: `lazyproperty.__get__` nested in another lazy getter didn't
  count, so turning caches into properties read +4.4% for +0.7% real calls. The gate now sums total calls.
- `lazyproperty` is a DATA descriptor: every access calls `__get__` (one pptx call), so lazy → property is call-neutral.
- Measuring 3.11 locally: `pip install uv`, `uv python install 3.11`, venv in scratchpad, `PYTHONPATH=src`.
  PYTHONPATH beats the editable install, so a `git worktree` of another commit can be timed the same way.
