## Objective
Fix what a code review of the merged v0.7.0 find/replace found (2026-10-16): errors that escape
as bare builtins, an error that depends on the deck's content, matches that don't compare equal,
a line break in the replacement written as `_x000B_`, regex anchors that misfire after a field
or line break, and an orphaned relationship. Owner decisions (2026-10-16): ship as a v0.7.1
patch; a `\v` or `\n` in `new` inserts a line break; regexes see the whole paragraph text.

## Goals
- **Errors up front.** `TextReplacer.__init__` checks the template against the pattern
  (`pattern.sub(new, "")` parses it eagerly), so a bad group number (`re.error`) or an unknown
  group name (`IndexError`) raises `InvalidValueError` whether or not anything matches. `count`
  that is not an `int` (or is a `bool`) raises `InvalidTypeError`.
- **Equal matches.** `TextMatch` compares by the elements it refers to (paragraph `a:p`, runs,
  shape) plus its offsets and text, and hashes by `(paragraph element, start, end)`. Before, two
  searches gave unequal matches, and a match with a `shape` could not be hashed.
- **Line breaks in `new`.** As in the `_Paragraph.text` setter, each `\v` or `\n` in the
  (expanded) replacement becomes an `a:br`. Each `a:br` and each following line's run copies the
  first touched run's `a:rPr`. When the match sits in one run, the text after it follows the last
  line. Oxml first: `CT_RegularTextRun.insert_lines_after(lines)`.
- **Regex context.** Each segment is searched in the paragraph text with
  `finditer(text, seg_start, seg_end)`. `^`, `\b` and lookbehind at a segment's start see the text
  before it (`^` only matches at the paragraph start). A match still ends at the segment end,
  which acts as the end of the text for `$` and lookahead.
- **Relationships.** `_remove_run` removes the run first, then drops each relationship the run
  referred to (any `r:` attribute) that nothing left in the part refers to. A run citing one rId
  twice no longer orphans it. Drops are batched per `replace_in()` call: one scan of the part per
  text frame with removals, not one per removed run. New helpers: `XmlPart.drop_unreferenced_rels()`
  and `CT_RegularTextRun.rel_ids`, so the API layer no longer runs XPath itself.
