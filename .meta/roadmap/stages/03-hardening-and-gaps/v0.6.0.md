## Objective
Make `pypptx` viable for production workloads at scale: large decks (200+ slides), shape-heavy
slides (1000+ shapes), bulk reporting. Opening a deck should not hold every image in memory, and
no cached value may go stale after a mutation the API allows.

Scope (owner decision 2026-10-15): the performance remainder only. Four of the original seven goals
landed early: the profiling harness (PR #109), hot-path `qn`/XPath caches (PR #107), O(1) shape
lookup indexes (`tests/perf/bench_lookup.py`), `ShapeRange` bulk helpers (feature-gaps §24), and the
work-count gate (PR #123). Streaming save is dropped unless the lazy-blob measurement shows that
save, not load, holds the memory. Cross-run text stays v0.7.0.

## Goals
- **Lazy binary blobs.** Parts that are not XML (images, media, embedded packages, fonts, anything
  loaded as a plain `Part`) read their bytes from the source zip only when they are used. Today
  `_PackageLoader._parts` reads every member while the deck opens.
- **Caching audit.** Review every `@lazyproperty` (204 in 45 files at branch open) and the hand-rolled
  caches (shape name/id indexes, `_base_placeholder` from #123). Each one is either shown sound or
  fixed. A new cache is added only where a hot path recomputes a derived collection, and only with a
  measured win (#51 showed `paragraphs`/`runs` caching is a loss).

## Implementation

### A. Lazy binary blobs

**Source policy (owner decision 2026-10-15): paths lazy, streams eager.**
- *Path input* (`Presentation("deck.pptx")`): no handle is kept open after load, so there is no
  Windows file lock. Each lazy read reopens the zip.
- *Stream input* and *directory packages*: read eagerly, as today. The caller may close or reuse the
  stream, and directory packages are rare. Streams therefore get no memory win; the docs say so.

**Steps**
1. **OPC reader** (`opc/serialized.py`). For a path-backed `_ZipPkgReader`, keep each member's
   `ZipInfo` (CRC-32, uncompressed size) and add `blob_source(pack_uri)`. It returns a small
   `_LazyBlob` holding the absolute path, member name, CRC and size. `_LazyBlob.read()` reopens the
   zip, reads the member and checks the CRC and size against the values recorded at load. A
   mismatch, or a missing file, raises `PackageError` ("the source file changed or was removed after
   the presentation was opened"). A stream or directory reader returns the bytes themselves.
2. **Loader** (`opc/package.py` `_PackageLoader._parts`). Hand `PartFactory` the source instead of
   the bytes. `XmlPart.load` and `LazyXmlPart.load` resolve it to bytes at once, so XML parts behave
   exactly as today. Only `Part.load` (the binary path) keeps the source.
3. **`Part._blob` becomes a property.** It returns assigned bytes if there are any, and otherwise
   reads through the source **without caching**. The setter stores the bytes and drops the source.
   Subclasses (`ImagePart.sha1`, `_dpi`, `_px_size`, `MediaPart.sha1`, `EmbeddedXlsxPart`) already
   read `self._blob`, so they need no change. `ImagePart.__init__`'s duplicate `self._blob = blob`
   goes away. Add `Part._blob_size`, the size read from `ZipInfo` without touching the bytes.
   - *Why no cache:* a cached read would make every blob resident after the first save, or after
     the first `add_picture` (which hashes every image). Re-reading costs one decompression per
     access, and the image paths already cache what they derive (`sha1`).
4. **Dedupe prefilters.** Without these, the first `add_picture` on a loaded deck reads every image.
   - `_ImageParts._find_by_sha1` and `_MediaParts._find_by_sha1` (`package.py`) skip any part whose
     size differs from the new image's before computing its `sha1`.
   - `PresentationPart._import_part` and the slide copier's `_find_identical` (`parts/presentation.py`)
     compare content type, then size, before comparing bytes. They also stop serializing every
     `XmlPart` to compare it against a binary source.
5. **Save** (`OpcPackage.save`). `PackageWriter` already writes one part at a time, so peak memory
   during save is about the largest blob. When the save target is the source file
   (`os.path.samefile`), copy every lazy blob into memory *before* the writer truncates the file.
6. **Docs.** The `Presentation()` docstring and the getting-started page describe the policy: a path
   source must not be changed or removed while the presentation is still to be saved, and a stream
   source is read in full.

**Measurement**
- New corpus spec `IMAGES_100` in `tests/perf/corpus.py`: 100 *distinct* images (128×128 RGB noise
  PNGs generated with Pillow). The existing specs reuse one PNG, which `add_picture` dedupes by
  SHA-1, so `large`'s "10 images" is a single image part.
- `run_baseline.py` gains an `images_100` row: `tracemalloc` current and peak after open, peak
  across open plus save, and wall-clock for open and save. The rows are captured before step 1 and
  again after step 5, and both go into `.claude/context/performance.md`.
- Streaming save stays dropped unless the after-numbers show that save's peak, not open's,
  dominates.

### B. Caching audit

**Method.** List every cache and put it in one bucket, each with a default test of soundness:
1. **Fixed-element proxies.** The property wraps `self._element` or a child no API removes, and the
   proxy re-reads XML on each access. Sound by construction; still confirm that no API replaces
   the child.
2. **Removable-child proxies.** The property wraps a child that an API can remove or replace (any
   `_remove_*`, `clear`, or a `get_or_add` that can swap the child). Risk: the proxy keeps holding
   the detached element.
3. **Snapshots.** The property stores a computed value: a list, dict, hash or size. It is stale
   after any mutation of its inputs.
4. **Part-graph lookups** (`core_properties`, `comment_authors`, `_image_parts`, layout and master
   lookups). Stale if the relationship is dropped or re-targeted.
5. **Transient internals** (`_PackageLoader`, `PackageWriter`, `_ContentTypesItem`). The object
   lives for one call, so these are sound by lifetime.

Record the result in `.claude/context/caching-audit.md`, linked from `performance.md` and the
context README. It is a table of symbol → bucket → verdict → reason or test. Buckets 1 and 5 may
be recorded as a group under the rule that makes them sound; any exception gets its own row.

**Leads confirmed at branch open (2026-10-15).** Fix these first, each with a failing test:
- **L1: stale shape name index** (`shapes/shapetree.py` `_get_name_index`).
  - After `shape.name = "B"`, `get_by_name("B")` returns `None` and `get_by_name("A")` still returns
    the renamed shape.
  - After the long-standing delete idiom `sp.getparent().remove(sp)`, `get_by_name` returns a shape
    that is no longer in the tree, while `len(shapes) == 0`.
  - `__contains__(str)` and the id index share the flaw.
  - Fix direction: validate on hit. The hit must still be a member of this tree and its name or id
    must still match; otherwise rebuild the index once. That is O(1) per lookup and catches every
    mutation path, raw XML included.
  - This also corrects the old claim that "invalidation triggers only on actual mutation": the
    index never noticed renames.
- **L2: stale `ImagePart.sha1` / `MediaPart.sha1`.** Assigning `part.blob = ...` keeps the old
  hash, so `_find_by_sha1` can match an image that is no longer in the part. Fix: the `Part._blob`
  setter (step A3) clears the derived caches. Land L2 before A3 because both touch the setter.

**New caches.** Candidates come only from the cProfile top 20 of the branch-open baseline re-run.
Each one ships only if the work-count gate or the wall-clock baseline improves, and the numbers go
in `performance.md`.

## Out of scope
- Multi-threaded or async save. The OPC zip and `lxml` trees are not thread-safe.
- Lazy loading of streams or directory packages, and a `lazy=` keyword (owner decision above).
- Lazy XML parts beyond what `LazyXmlPart` already defers. XML is still read at load.
- Copying compressed zip members raw on save. `zipfile` has no public API for it, so untouched blobs
  are decompressed and recompressed as today.
- New feature surface. If a benchmark needs a missing API, file it for v0.7.0.
- Native (C-extension) optimizations.
