## Objective
Solve the most-requested ergonomic gap in text editing: find / replace
operations that work correctly across XML run boundaries. PowerPoint splits a
single visual word across multiple `<a:r>` runs to preserve fine-grained
formatting; naive string operations break this. Provide reliable helpers that
preserve run formatting where possible and gracefully degrade where not.

Scope (owner decisions 2026-10-15):
- **Deck-wide.** Find/replace on a text frame and a paragraph, plus a deck-wide sweep on a slide
  and on the presentation.
- **Property-based test** with `hypothesis`, already a dev dependency
  (`tests/oxml/test_simpletypes_properties.py`), so nothing new is added.

## Goals
- `TextFrame.replace(old, new, *, count=None, regex=False)` and `TextFrame.find_all(pattern, *,
  regex=False)`, with the same pair on `_Paragraph`. Matches may span runs; replaced text takes
  the formatting of the first run it touches.
- `Slide.replace_text()` / `Presentation.replace_text()` and `find_text()`. They cover every
  slide shape with text (group members and table cells included) and existing notes slides.
- Traversal helpers: `TextFrame.iter_runs()` and `TextFrame.iter_chars()`.
- `merge_runs()`: merge adjacent runs whose formatting is the same, ignoring the proofing state
  PowerPoint stores on runs. It is not run automatically.
- Document the limitation around `Lines()` (per `feature-manifest.md` — requires a rendering
  engine and stays out of scope).

## Implementation

### The text model

A paragraph's text is its `a:r`, `a:br` and `a:fld` children in document order
(`CT_TextParagraph.content_children`), the same string `_Paragraph.text` returns. A line break
reads as `"\v"` and a field as its current text.

- **Matching works within a segment.** A segment is a maximal sequence of consecutive `a:r`
  elements. `a:br`, `a:fld` and any other child are boundaries, so a match never crosses a line
  break, a field or a paragraph:
  - a field's text is regenerated by PowerPoint (slide number, date), so editing it is pointless;
  - a line break has no text to edit.
- **Offsets are into `paragraph.text`**, so `paragraph.text[m.start:m.end] == m.text` always holds.
- **Search sees what `run.text` returns.** That is the raw `a:t` text: a control character stored
  as `_x0007_` is not decoded, as today.
- **Why splits matter.** In the real-world corpus (28 decks), 109 of 998 slide paragraphs have more
  than one run. Of their 205 adjacent run pairs, 13 have identical `a:rPr`, and 57 more differ
  only in proofing state: `err` 30, `smtClean` 23, `dirty` 4. So about a third of all run
  boundaries are invisible to the reader.

### Steps (bottom-up, types first)

1. **OXML** (`oxml/text.py`).
   - `CT_TextParagraph.run_segments()` returns each segment as `(start_offset, [a:r, ...])`, with
     offsets into the paragraph text.
   - `CT_TextCharacterProperties.formatting_key()` returns a hashable form of the properties:
     attributes minus the proofing-state set (`dirty`, `err`, `smtClean`, `smtId`), plus the
     serialized children. A run with no `a:rPr` has the empty key.
2. **Search engine** (new `text/search.py`): `TextMatch` and the find logic, as pure functions
   over a paragraph element.
   - `pattern` is a `str` (literal unless `regex=True`) or a compiled `re.Pattern`. A compiled
     pattern implies regex and keeps its flags, e.g. `re.IGNORECASE`.
   - Matches are non-overlapping and in document order: `re.finditer` per segment, with a literal
     pattern passed through `re.escape`.
   - An empty literal pattern raises `InvalidValueError`. Zero-width regex matches are skipped.
   - `TextMatch` is immutable: `paragraph`, `paragraph_index` (0 at paragraph scope), `start`,
     `end`, `text`, `runs` (the `_Run`s the match touches, in order) and `shape` (set by the slide
     and presentation searches, `None` otherwise).
3. **Replace** (`text/search.py`, exposed on `TextFrame` and `_Paragraph`). Returns the number of
   replacements made.
   - Matches are found per paragraph and applied right to left, so earlier offsets stay valid.
   - **Within one run:** splice the run's text; its formatting is untouched.
   - **Across runs `r_i … r_j`:** `r_i` gets prefix + new text (so the new text takes `r_i`'s
     formatting), the runs between are removed, and `r_j` keeps only the suffix with its own
     formatting.
   - **A run left empty is removed.** The paragraph's `a:endParaRPr` keeps its formatting for the
     paragraph end.
   - **Removing a run with a hyperlink** (`a:hlinkClick`/`a:hlinkMouseOver` `r:id`) calls
     `part.drop_rel(rId)` *before* the element goes. `drop_rel` drops the relationship only while
     the part's reference count is below 2, so it must be called while the run still counts.
   - `regex=True` expands `new` as a template (`match.expand`, so `\1` and `\g<name>` work).
   - `count=None` replaces all; `count=0` is a no-op; a negative count raises `InvalidValueError`.
     The count applies across the whole frame, slide or presentation, in document order.
4. **Traversal and merge** (`text/text.py`).
   - `TextFrame.iter_runs()` yields every `_Run` in document order. Fields are not runs.
   - `TextFrame.iter_chars()` and `_Paragraph.iter_chars()` yield
     `TextChar(char, paragraph_index, offset, run)` for every character of every paragraph's text.
     `run` is `None` for `"\v"` and for field text.
   - `merge_runs()` on `TextFrame` and `_Paragraph` merges adjacent `a:r` with equal
     `formatting_key()` into the first of them, and returns the number of runs removed.
5. **Deck-wide** (`slide.py`, `presentation.py`): `Slide.find_text()` / `Slide.replace_text()` and
   `Presentation.find_text()` / `Presentation.replace_text()`, with the same arguments as the frame
   methods.
   - **What they cover, in order:** every shape with a text frame in shape-tree order, recursing
     into groups; each cell of each table, row by row; then the slide's notes slide if it has one.
     Slides go in presentation order.
   - **Never creates a notes slide.** Notes are guarded by `has_notes_slide`, because
     `SlidePart.notes_slide` adds one when it is missing.
   - **Not covered:** slide layouts and masters (template text), chart text, SmartArt node text and
     comments. Inherited placeholder prompt text ("Click to add title") is not in the slide XML, so
     it is never matched.
6. **Docs and examples.**
   - API docstrings, and the Sphinx `text.rst`/`presentation.rst` pages list the new members.
   - `examples/batch_process.py` uses `Presentation.replace_text()` and reports replacements, not
     runs changed. Its per-run loop misses words split across runs.
   - `feature-manifest.md` moves "Find / replace across runs" from gaps to implemented, and keeps
     `InsertBefore`/`InsertAfter`/`Characters`/`Words` as gaps. Add a README feature line.

## Out of scope
- Visual line-break calculation. Documented in `feature-manifest.md` as inherently
  out of scope (requires rendering engine).
- Smart formatting reconciliation across spanning replacements (e.g.
  "preserve bold from middle run when replacing across three runs"). The
  documented behavior is "match first run's formatting"; smarter merging is
  future work.
- Word / sentence boundary navigation (`Words()`, `Sentences()` in VBA).
  Outside scope for v1.0; can revisit post-1.0.
- Matches across paragraphs, line breaks or fields, and editing field text.
- A callable replacement (`re.sub`-style `repl` function). `new` is a string, or a template in
  regex mode.
- Layout, master, chart, SmartArt and comment text in the deck-wide sweep.
- Running `merge_runs()` automatically after a replace. It changes XML beyond the match, so it is
  opt-in.
- `InsertBefore()` / `InsertAfter()` / `Characters()` (VBA). These stay gaps in the manifest.
