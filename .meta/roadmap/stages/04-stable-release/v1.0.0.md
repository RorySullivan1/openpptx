## Objective
Ship a stable, documented 1.0 that commits to SemVer: declare the public surface, publish the
reference docs, and put the package on PyPI. Everything from v0.1.0 to v0.7.1 was foundation work.
This is a release milestone, not a feature one.

Facts found when the card was filled in (2026-10-16):
- The PyPI name `pypptx` belongs to an unrelated 2015 project (juanpabloaj, "Create a pptx from
  plain text", 0.1.0 to 0.2.2). The README's `pip install pypptx` installs *that* package today.
- The repo has no root LICENSE, and the code descends from python-pptx (MIT, © Steve Canny):
  `xmlchemy`, `cxml`, `lazyproperty`, the `Describe*` test style. MIT requires its notice.
- Public top-level names: about 270 in the API layer (top-level modules, `chart`, `dml`, `enum`,
  `shapes`, `text`) and about 470 more in `oxml`/`opc`/`parts`, none with an underscore.
- Already in CI on 7 cells: the full suite, the real-world corpus round-trip and the example scripts.
  The work-count perf gate runs on ubuntu/3.11. 1.0 keeps these green and adds none of them.

Owner decisions (2026-10-16):
- **Distribution name `openpptx`.**
- **Complete rebrand** (owner, later the same day): every live reference to `pypptx` becomes
  `openpptx`, and so does the repo (`RorySullivan1/openpptx`). History (shipped cards, session
  logs, release-tags) keeps the old name. The public base exception `PyPptxError` becomes
  `OpenPptxError`.
- **Import name `openpptx` too** (owner, later again): the package moves from `src/pptx/` to
  `src/openpptx/`, so `from openpptx import Presentation`. There are no users yet, so nothing
  renamed before 1.0.0 gets a deprecation shim, `PyPptxError` included. The policy starts at 1.0.0.
- **Contract = the documented surface.** `oxml`, `opc`, `parts` and anything with an underscore
  are internal by policy and are not renamed. A snapshot test guards the public names.
- **Docs on GitHub Pages**, deployed by a workflow.
- **Provenance: derived from python-pptx.** The LICENSE carries python-pptx's notice too.

## Goals
- **Rebrand to `openpptx`.**
  - Done in step 1: every live mention of `pypptx` (pyproject `name`, README, docs, docstrings,
    examples, tests, CLAUDE.md, `.claude/`); the import package `pptx` → `openpptx`;
    `PyPptxError` → `OpenPptxError`; the default template's core properties, which said "generated using python-pptx" and
    last modified by "Steve Canny"; the GitHub repo name.
  - Still to do: add
  `[project.urls]` (Homepage, Documentation = the Pages URL, Source, Issues), classifiers
  (`Development Status :: 5 - Production/Stable`, Python 3.9 to 3.13, `Typing :: Typed`), a
  `readme` and keywords.
- **License.** Add a root `LICENSE`: the owner's MIT notice followed by python-pptx's copyright
  and permission notice, copied verbatim from its upstream LICENSE. Set `license-files =
  ["LICENSE"]`. The README credits python-pptx.
- **Public API contract.** Add a docs page, `docs/stability.rst`. The public surface is every
  module documented under `docs/api/` plus `openpptx.exc`. Internal: `openpptx.oxml`, `openpptx.opc`,
  `openpptx.parts` and any `_`-prefixed name. Steps:
  - Audit each API-layer module for naming, return types and exception contract. Bare
    `ValueError`/`TypeError` raised in user-facing paths become `openpptx.exc` types.
    `InvalidValueError`/`InvalidTypeError` already subclass the builtins, so this is not breaking.
  - Every API-layer module either gets a `docs/api/*.rst` entry or is declared internal. Modules
    to check for coverage: action, media, comments, search, transitions/animation, theme, SmartArt,
    chartex, custom shows, fonts, tags.
  - A stray public helper in the API layer gets an underscore, with no shim: there are no users
    before 1.0.0.
  - New `tests/test_public_api.py` snapshots the public names of each public module. Changing
    that set fails the test until the snapshot is updated on purpose.
- **Deprecation and SemVer policy** (on the stability page, stated in the README):
  - Breaking change = removing or renaming a public name, or changing a signature or the
    exception contract.
  - A deprecated name warns from the minor release that deprecates it and stays for the whole
    1.x line. Removal waits for 2.0, which is what SemVer requires.
- **Docs.**
  - Narrative guides per area: slides, shapes, text (including find/replace), charts, effects,
    theme. Runnable `examples/` are linked inline.
  - A migration guide for python-pptx users covering new enums, wider chart coverage (chartex,
    3D), the exception hierarchy, find/replace and renames. The import changes from `pptx` to
    `openpptx`, so the two libraries can be installed side by side.
  - New `.github/workflows/docs.yml` runs `sphinx-build -W -E` and deploys to Pages on `main`.
- **CHANGELOG.md** in Keep a Changelog form, with one entry per version from v0.1.0 to 1.0.0. Built
  from the version cards and `.meta/release-tags.md`.
- **Release pipeline.** New `.github/workflows/release.yml`: when a tag `v*` is pushed it builds
  the sdist and wheel, runs `twine check`, and publishes to PyPI by Trusted Publishing
  (environment `pypi`), with no token in the repo. `1.0.0rc1` goes first: a pre-release, so a plain
  `pip install openpptx` skips it. Tags from here on are annotated and `v`-prefixed.
- **Version 1.0.0** in `pyproject.toml` and `openpptx.__version__`.
